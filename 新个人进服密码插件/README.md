# 新个人进服密码插件

给服务器加**第二道门**：进服时不只要证明"你是谁"（账号 / GUID），还要报一个**只有你知道的密码**。

防的是**凭据被盗用顶号** —— SCKey token 或游客 GUID 被别人拿到后，他不需要知道你的任何密码就能以你的身份连进来，于是你的存档、领地、背包都成了他的。本插件让进服多要一个密码，把门槛抬高。

> ⚠️ 它**不是加密**，是**第二因素**。别人若同时拿到了你的凭据**和**密码，那还是你。

---

## 和旧版「个人进服密码插件」的区别

| | 旧版（`personal-code`） | 本插件 |
|---|---|---|
| 密码谁来设 | **服主**用 `/setpc add 名字 密码` 一个个设 | **玩家自己**用 `/pwd set` 设 |
| 密码怎么存 | **明文**存 JSON | **PBKDF2-SHA256**（20 万轮 + 随机盐），明文不落盘 |
| 密码怎么比 | 明文比对 | 哈希比对 + 定长比较（防侧信道） |
| 主键 | 社区ID + 昵称 | **玩家 GUID**（改名不丢、同名不串） |
| 全服默认密码 | 无 | 有（`DefaultPassword`），可留空 |
| 可选模式 | 无 | 有（默认密码留空 = 没设密码的人直接放行） |
| 连错处理 | 直接拒连，无计数 | GUID 与 IP 双维度计数 + 5 分钟衰减 + 超限断线 |
| 密码回显 | `show` 打码 | 一律不回显任何密码 |
| 客户端交互 | 服主设完再通知玩家 | 玩家在游戏内自助，走客户端密码框 |

**两者可以同时装吗？** 不建议。双方都挂 `BanEventManager.IsBan` 同一个钩子，核心是 `foreach` 遍历、**任一返回 true 即拒绝**，同时启用会互相干扰。要换成本插件请先把旧版 DLL 移出 `Plugins/`。

## 安装

1. 把 `new-personal-code.dll` 放进服务端 `Plugins/` 目录（**文件名可以随意**，配置目录由代码写死）。
2. 重启服务器。首次运行会自动生成 `Plugins/新个人进服密码插件/进服密码配置.json`。
3. **默认是关的**（`Enabled: false`）。把 `Enabled` 改成 `true` 后重启，插件才会接管进服流程。

> 为什么默认关：安全增强不应该在装上的那一刻就改变全服登录流程 —— 万一配置没配好，服主自己就被锁在门外了。

## 配置

文件：`Plugins/新个人进服密码插件/进服密码配置.json`

```json
{
  "Enabled": false,
  "DefaultPassword": "",
  "AdminPassword": "",
  "AdminSessionMinutes": 120,
  "MaxFailuresBeforeKick": 5,
  "MaxFailuresBeforeIp": 8,
  "MinLength": 4,
  "MaxLength": 16,
  "LogStats": true
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `Enabled` | `false` | 总开关。关掉时插件完全不接管，服务器行为与原生一致（不弹框、不校验） |
| `DefaultPassword` | `""` | 全服默认密码。**留空 = 可选个人保护模式**（见下）。支持 `sha256:<64位十六进制>` 只放哈希 |
| `AdminPassword` | `""` | 可选的服主提权密码，保护 `/pwd default` 与 `/pwd status`。留空 = 该闸门关闭 |
| `AdminSessionMinutes` | `120` | 一次提权验证的有效期（分钟）。`0` = 本次连接内一直有效 |
| `MaxFailuresBeforeKick` | `5` | 同一玩家连错几次断开**这一条**连接。`0` = 不踢 |
| `MaxFailuresBeforeIp` | `8` | 同一 IP 连错几次断开。`0` = 不按 IP 限 |
| `MinLength` / `MaxLength` | `4` / `16` | 密码长度范围。上限封死 16 —— 客户端密码框就那么宽 |
| `LogStats` | `true` | 每 5 分钟往日志打一行"放行 / 拒绝"统计 |

### 两种工作模式

**① 可选个人保护模式（默认，`DefaultPassword` 留空）**

没设个人密码的人**直接放行**；设了的人才需要报密码。适合"只想给在意的人（服主、管理员、VIP）加一道锁，不打扰其他人"。

**② 全员门槛模式（`DefaultPassword` 非空）**

没设个人密码的人必须用这个默认密码进门。适合"地址泄露了，想临时挂个全服口令"。

> 无论哪种模式，**个人密码永远优先**：设了自己密码的人不会被默认密码挡下，也不会因为没记住默认密码而进不来。

## 命令

| 命令 | 谁能用 | 说明 |
|---|---|---|
| `/pwd` | 所有人 | 看自己的状态：有没有个人密码、下次该敲哪个 |
| `/pwd set ＜密码＞ ＜确认密码＞` | 所有人 | 设置 / 修改自己的个人密码（要打两遍，防手滑） |
| `/pwd clear` | 所有人 | 删掉个人密码 |
| `/pwd ＜密码＞` | 所有人 | 拿一串东西测一下是不是自己的密码 |
| `/password ...` | 所有人 | `/pwd` 的**别名**，两个名字都能敲 |
| `/pwd default ＜密码＞` | 服主 | 设全服默认密码 |
| `/pwd status` | 服主 | 看有多少人设了个人密码、累计拦截次数、存储路径 |
| `/pw ＜密码＞` | 服主 | 验证服主身份（配了 `AdminPassword` 才需要） |
| `/pw clear` | 服主 | 撤销验证 |

服主命令的判定**不信任 `PlayerData.ServerManager`** —— 客户端可以在进服包里自称管理员，也可能被外挂通过自定义包写成 `true`。唯一客户端碰不到的秘密是密码，所以配了 `AdminPassword` 时必须先 `/pw` 验证。

## 玩家视角的完整流程

```
① 玩家点服务器 → 因为本插件把 m_needPasswd 覆写成 true，客户端弹出密码框
② 玩家敲密码 → 随握手包一起发给服务端
③ 服务端 AcceptAclient 前缀里校验：
     设过个人密码 → 比个人密码
     没设 + 默认密码为空 → 放行
     没设 + 默认密码非空 → 比默认密码
④ 通过 → 正常进服；失败 → 回"密码错误"，累计计数，超限断线
```

管理员要在游戏内给玩家设密码？不需要 —— 让玩家自己 `/pwd set` 就行。

## 工作原理（给想改代码的人）

核心其实有官方扩展点 `PasswordValidationEventManager`（`IPasswordValidationEventHandle`），看起来应该直接用它。**但它是死代码**：`AcceptAclient` 里那句 `else if (!string.IsNullOrEmpty(password))`（`password` 取自 `WorldSettings.Password`）把整段校验包住了 —— 房间密码为空时 `ValidatePassword` 根本不会被调用，事件管理器一次都不会触发。所以本插件用 **Harmony** 接管，两处补丁缺一不可：

1. **`ServerInfoPackage..ctor(bool)` 后缀** —— 把 `m_needPasswd` 覆写成 `true`。客户端 `NetPlayScreen` 靠这个字段决定点列表时弹不弹密码框。不改这里，玩家看不到输入框，密码永远送不上来。（注意它读的是 `WorldSettings.Password`，我们**不去改那个世界设置** —— 改了会跟着存档存下来、还会被别的界面读到。）
2. **`ConnectionRequestPackage.AcceptAclient` 前缀** —— 真正的校验点。

### ⚠️ 两个踩过的大坑

**坑一：prefix 校验失败时返回 `false` 会让客户端卡住。**
Harmony prefix 返回 `false` 会跳过 `AcceptAclient` 的**整个方法体**，而"把 `connectionError` 发给客户端"那一步恰恰就在那个方法体里。返回 `false` 等于既不拒绝也不接受，客户端一直卡在《连接中》直到超时，玩家根本看不到《密码错误》。
**正确做法**：把文案写进 `connectionError` 再**返回 `true`**，由核心原有的 `ConnectionRejectPackage` 流程发拒绝包。

**坑二：断线绝对不能用 `netNode.Stop()`。**
`Stop()` 只是设 `isStopping=true`，随后 `StopImmediate()` 在 `WorkType==Server` 分支里会 `RemoveAllClients("服务器主动关闭")` + `netManager.Stop()` —— 那是**关掉整个游戏服务器**，不是踢某个人，而且**不会自动恢复**（实测曾导致全服 22 小时进不去：进程还活着、日志还在自动存档，极难凭直觉发现）。
**正确做法**：`netNode.SendWriterFromPackage(new ConnectionRejectPackage(文案), pkg.From.Request, reject: true)` —— `reject:true` 内部只做 `request.Reject()`，关的是**这一条**连接，监听端口和其他在线玩家完全不受影响。

### 为什么用 GUID 而不是昵称

GUID 是核心在握手包里解析出来的身份（SCKey 模式取 `m_SCKeyGuid`，游客模式取 `m_guestGuid`）。用昵称当键的话，改名就丢记录、同名会互串。游客 GUID 虽然客户端可以自选，但那本来就不是本插件能收紧的东西 —— 核心给什么就用什么。

### 为什么失败计数要按 IP 也来一份

扫码 / 第三方入口进来的客户端 GUID 全是 `00000000-0000-0000-0000-000000000001` —— **所有人共用同一个 key**。只按 GUID 计数会互相连坐：一个倒霉输错 5 次就把同入口的其他人一起连坐。所以两个维度都要留，**取任一超限即踢**。

## 文件布局

```
Plugins/新个人进服密码插件/
├── 进服密码配置.json      # 配置（首启自动生成）
└── 进服密码.json          # 个人密码库（PBKDF2 哈希，无明文）
```

密码库结构：

```json
{
  "Format": 1,
  "Players": {
    "9f2c...（GUID 无横线小写）": {
      "Salt": "base64...",
      "Hash": "base64...",
      "CreatedUtc": "2026-10-10 15:00:00"
    }
  }
}
```

## 注意事项

- **密码是第二因素，不是加密**。凭据和密码同时泄露 = 你还是会被顶号。
- 默认密码（`DefaultPassword`）是**明文存配置**的，配置属敏感文件，别放进公开可访问的目录。要更安全就写 `sha256:<哈希>`。
- 个人密码**只存哈希，找不回来**。忘了只能 `/pwd clear` 后重设。
- 密码里**不能有空格** —— 客户端密码框只认一串连续字符。
- `/pw` 的密码会出现在**玩家自己**的聊天行里（客户端回显命令，服务端无法阻止），所以别用别处在用的密码。
- 本插件**只管进服这一步**，进服之后该有的权限一点没少，不做任何降权。
- 与其他准入类插件（白名单等）**互斥**，都占用同一个准入判定钩子，二选一。
